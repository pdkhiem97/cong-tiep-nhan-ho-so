## Project

DuHoc24 is a study-abroad application portal and the sample repo for a 6-week programming course. The homepage chatbot calls Gemini for real; everything else is still the **Week 1** state: static UI on mock data, with no database or auth. The README's week-by-week roadmap defines what comes later (Supabase, document extraction, Make.com automation, magic-link login). Don't build ahead of it unless asked. In particular, `/login` is deliberately absent because students build it in Week 6.

User-facing copy is Vietnamese, and so are the README and code comments. Keep new UI text in Vietnamese.

## Commands

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
npm run lint    # ESLint flat config: next core-web-vitals + typescript
```

There is no test framework, so there are no test commands. There is also no typecheck script: `npx tsc --noEmit` works, but `LayoutProps<"/">` in `app/layout.tsx` is a route type generated by Next, so run `next dev`, `next build`, or `next typegen` first on a fresh clone.

The chatbot needs `GEMINI_API_KEY` in `.env` or `.env.local`; the other pages run without it. `.env.example` also lists the Supabase and site URL variables for later weeks.

## Architecture

**Three surfaces share one root layout.** `app/layout.tsx` only sets the font (Be Vietnam Pro, including the Vietnamese subset) and global CSS, with no site chrome:
- `/`: the landing page composes `components/landing/*`.
- `/portal`: the student view. It renders `SiteHeader` itself and is built from `components/portal/*`.
- `/admin/*`: `app/admin/layout.tsx` adds the sidebar. `/admin` redirects to `/admin/requests`. These pages have no access control yet.

**Page data comes from `lib/mock-data.ts`.** It holds both the domain types and the hard-coded records, and it is the seam that Supabase replaces from Week 3. Pages are server components that import from it directly; `components/portal/*` receive data as props.

**The chatbot is the only real backend.** `ChatWidget` posts the session's conversation to `app/api/chat/route.ts`, which calls Gemini (`gemini-3.5-flash-lite`) on the server so the key never reaches the browser. The bot may only answer from the Q&A set in `lib/chat-qna.ts`, enforced by the system instruction there; edit answers in that file. Conversations are not saved, and the route has no rate limiting.

**Other interactions are simulated.** Expect these to look more functional than they are:
- `QuoteForm` only sets local state on submit and shows a "quote sent" message. Nothing is saved or emailed.
- `/portal` shows the fixed `currentStudent` record. Its `matches` are hand-written rather than computed by comparing GPA/IELTS against `schools`, and the submit button has no handler.

**Status values are Vietnamese snake_case codes** (`DocStatus`, `RequestStatus`, `ServicePackage`, such as `cho_duyet` and `can_nop_lai`). The types are in `lib/mock-data.ts`; their labels, tones, and icons are mapped in `components/status-badge.tsx`. A new status needs an entry in both files.

## UI conventions

- shadcn/ui uses the `base-nova` style, built on **Base UI (`@base-ui/react`), not Radix**. Component APIs differ from Radix-based shadcn examples; for instance, `Select`'s `onValueChange` can pass `null`. Check the local `components/ui/*` file before using a component.
- `components.json` also registers the `@tailark-oss` block registry, the source of the landing page's base blocks.
- Tailwind v4 has no config file. Design tokens are CSS variables in `app/globals.css`.
- Add `"use client"` only to components that need interactivity.
- `next/image` remote images are limited to `images.unsplash.com` (`next.config.ts`).

## Known doc mismatches

- The README roadmap mentions `/schools`, but the only schools route is `/admin/schools`.
- The README still describes the repo as UI-only, with the Week 2 chatbot items unticked.
